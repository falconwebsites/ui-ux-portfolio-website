Designing the control room for institutional gold trading.

A deep dive into redesigning the listing tables, detail views, and workflows for XBI Mutual Fund's back-office operations portal.

Note: Client name has been anonymized to XBI Mutual Fund to comply with NDA terms. UI details and workflows have been generalized while preserving core product logic.

Role UI/UX Designer
Type Enterprise Product

01
The context

What is a Back-Office (BO) portal?

When everyday users invest in a mutual fund, they see a simple app screen. But behind the scenes, massive institutional deals take place—such as SBI Mutual Fund purchasing kilograms of physical gold to back their investment schemes.

This portal is the Back-Office (BO) control room. It is where internal operations staff handle the heavy lifting: tracking multi-lakh trades, managing bank transfers, generating legal paperwork, and maintaining compliance records.

The design goal was to turn a heavy, complex maze of financial data into a clean, scannable system where operators can work fast without making high-stakes errors.

02
The workflow

How a trade moves through the system

To understand the UI, you first need to understand how a deal happens. Every transaction follows a strict safety-first lifecycle involving two key operational roles:

1. The Maker (e.g., Hawkins Maru): The operator who logs the initial trade data into the system (e.g., buying 4 KGs of gold for ₹50,00,000 from a vendor like Augmont). When entered, the trade status is marked as Entered or Pending.

2. The System Deal Confirmation (DC): Once a trade is logged, the system automatically generates a formal trade receipt called a Deal Confirmation (DC).

3. The Checker (Supervisor): A separate senior staff member who reviews the entered details, checks valuation files, and clicks Authorize so money can securely move via bank networks like RTGS.

The step-by-step lifecycle of a trade from data entry to final authorization.
03
The listing page

Anatomy of a transaction row

The listing page is the master dashboard where operators monitor hundreds of active deals. Because space is valuable, every single row in the table is packed with essential metadata designed to be read at a single glance.

What data lives in each row?

  • ID & Dates: Unique transaction ID (e.g., ID 01) alongside the transaction date and value settlement date.
  • Financials & Assets: Exact quantity in kilograms (e.g., 4 KG) and total deal value in INR (e.g., ₹50,00,000).
  • Banking & Partners: The deposit bank used (like HDFC or ICICI) and the wholesale counterparty/vendor (like Augmont).
  • Logistics: Security type (GOLD), vault location (Delhi, Mum), and settlement tenor (e.g., T or T+1).

Status Badges & Inline Actions: Each row features a live status tag (like Entered, Authorized, or DC Generated). Next to these, we placed inline document icons and action links (such as Email DC or instant PDF downloads).

UX Detail: When a deal is brand new, these icons are hidden. They only light up dynamically once the transaction reaches a valid stage, preventing operators from trying to download documents that don't exist yet.

The listing table showing row data breakdown, status badges, and inline quick-download icons.
04
Bulk actions

Batch processing heavy workloads

Operations teams often handle dozens of similar trades executed on the exact same day. Clicking into every single row to perform individual approvals or generate bank documents would create massive bottlenecks and human fatigue.

To solve this, I designed a Bulk Actions menu at the top of the table. By selecting multiple row checkboxes, operators can execute batch operations instantly:

  • Authorise / Reject: Mass-approving or declining a selected group of trades.
  • Custodian Instruction: Generating vault storage paperwork in bulk.
  • RTGS / NEFT Letter: Issuing combined institutional bank transfer payment instructions.

Checkbox multi-select

Allows operators to select rows in bulk to apply simultaneous commands.

Batch bank letters

Generates single-file RTGS payment letters for multiple trade orders at once.

Inline shortcuts

Provides one-click file downloads straight from the row without extra navigation.

Bulk action dropdown allowing users to process multiple rows simultaneously.
05
The detail view

Deep-dive inspection and next actions

When an operator clicks on a specific row from the listing page (e.g., ID 02), they enter the Detail View. This page is structured to provide deep inspection without visual clutter.

What lives on the detail page?

  • Metadata Grid: Full breakdown including Scheme Name (SBI MF Gold ETF), Deposit Type (RTGS), Quantity in KGs, Unit mapping (1 KG = 1000 Units), and Deposit Dates.
  • Guided Action Button: A prominent primary CTA (e.g., NEXT ACTION: AUTHORIZE DC) that explicitly tells the user what operational step to perform next, preventing guesswork.
  • Files Generated Section: Direct download links for compliance files created during this trade lifecycle, such as Custodian Instructions and Deal Confirmations.

The detail view layout showing complete record metadata and guided next-action triggers.
06
Audit trail

Tracking every action on the right sidebar

In institutional finance, complete accountability is mandatory. Regulators need to know not just where a transaction stands, but its exact historical timeline.

On the right side of the detail page, I designed a Remarks & Activity Sidebar. This is a chronological audit trail that logs every single action down to the minute:

  • “Valuation File was authorized by Ms. Jane Smith — 48 min ago”
  • “Custodian Instruction was generated — 32 min ago”
  • “This Transaction has been authorized — 20 min ago”

This persistent sidebar ensures absolute transparency, protecting the institution against compliance risks or audit failures.

The chronological remarks sidebar providing real-time transparency and audit history.
07
Key design decision

Structuring data density instead of hiding it

A common trap in enterprise UX is trying to make complex financial software look like a minimalist consumer app by stripping away information.

However, back-office operators need to see transaction values, bank codes, tenors, and PAN numbers simultaneously to do their jobs correctly.

Instead of hiding data, my design decision was to organize and structure complexity: using scannable table rows, conditional action icons that appear only when relevant, and guided next-step buttons to reduce cognitive load.

Data-rich rows

Displayed complete trade attributes directly in the table to minimize unnecessary clicking.

Contextual tools

Used dynamic icons and bulk dropdowns so actions match the exact lifecycle state.

Clear accountability

Paired a guided detail view with a persistent audit timeline for total security.

08
Final experience

A clear, controlled digital control room

The final design successfully transforms a complex institutional operation into a smooth, transparent experience.

From scannable listing rows and instant document downloads to secure maker-checker details and robust audit trails, operations teams can now manage heavy multi-lakh asset flows with speed, absolute clarity, and confidence.
